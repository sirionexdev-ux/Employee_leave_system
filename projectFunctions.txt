# Employee Leave Management System
---

## 1. Project Overview

The Employee Leave Management System allows an organization to manage employee leave information.

The application provides functionality to:

- Display all employees
- Apply for leave
- Check leave balance
- Display employee details
- Display leave history
- Display employees currently on leave
- Display available leave types
- Exit the application



---

# 2. Project Goal

Instead of putting everything inside one large `while` loop, the application is divided into multiple functions.

### Basic idea

```text
Large Program
     ↓
Identify responsibilities
     ↓
Create functions
     ↓
Connect functions
     ↓
Add generators
     ↓
Add decorators
     ↓
Complete Mini Backend
```

# 12. Leave History Flow

This part demonstrates a **Generator**.

```text
Main
  ↓
display_leave_history()
  ↓
leave_history_generator()
  ↓
yield record 1
  ↓
yield record 2
  ↓
yield record 3
  ↓
...
```

Instead of returning all records at once:

```python
return leave_history
```

the generator provides records one at a time:

```python
yield leave
```

This becomes useful when the application has a very large amount of data.

# 14. Decorator Architecture

The project uses:

```python
@log_activity
```

above important functions.

Example:

```python
@log_activity
def apply_leave(...):
    ...
```

Python effectively treats it like:

```python
apply_leave = log_activity(apply_leave)
```

The structure is:

```text
              log_activity()
                    │
                    ▼
                wrapper()
                    │
              ┌─────┴─────┐
              │           │
        Before function    │
              │            │
              ▼            │
        Print operation    │
                           ▼
                     Original function
                           │
                           ▼
                    Execute operation
                           │
                           ▼
                     Return result
```

---

# 15. Why `wrapper(*args, **kwargs)`?

The decorator may be applied to functions having different arguments.

For example:

```python
apply_leave(101, 2, 3)
```

and:

```python
check_leave_balance(101)
```

The decorator therefore uses:

```python
def wrapper(*args, **kwargs):
```

This allows the decorator to accept different numbers and types of arguments.

# 16. Function Arguments Used

This project intentionally demonstrates different argument types.

## Positional Arguments

```python
get_employee(101)
```

The value `101` is passed according to position.

---

## Default Argument

```python
def apply_leave(
    employee_id,
    leave_choice,
    number_of_days=1
):
```

If days aren't provided:

```python
apply_leave(101, 2)
```

Python uses:

```text
number_of_days = 1
```

---

## `*args`

```python
def print_message(*messages):
```

Can receive:

```python
print_message(
    "Leave approved",
    "Employee: Rahul",
    "Days: 2"
)
```

All values are collected into a tuple.

```text
messages
   ↓
("Leave approved", "Employee: Rahul", "Days: 2")
```

---

## `**kwargs`

```python
def create_leave_record(**details):
```

Called as:

```python
create_leave_record(
    employee_id=101,
    leave_type="Sick",
    days=2
)
```

The values are collected into a dictionary:

```python
{
    "employee_id": 101,
    "leave_type": "Sick",
    "days": 2
}
```

# 18. Why Each Data Structure?

## Dictionary

Used when we need:

```text
KEY → VALUE
```

Example:

```text
101 → Rahul
```

Useful for fast lookup using Employee ID.

---

## List

Used for:

```text
Multiple leave records
```

Example:

```text
[
    record1,
    record2,
    record3
]
```

---

## Tuple

Used for fixed data:

```text
Casual
Sick
Emergency
```

and:

```text
Menu options
```

---

## Set

Used when duplicates should not exist:

```text
{101, 104, 108}
```

If `101` is added again, the set remains:

```text
{101, 104, 108}
```

# 19. Backend-Style Design

Although this is a console application, it is designed to behave like a small backend system.

The conceptual architecture is:

```text
              USER
               │
               ▼
         MENU / INPUT
               │
               ▼
          MAIN PROGRAM
               │
               ▼
        BUSINESS LOGIC
               │
       ┌───────┼────────┐
       │       │        │
       ▼       ▼        ▼
   Validation  Leave   Employee
              Logic    Logic
       │       │        │
       └───────┼────────┘
               ▼
             DATA
               │
       ┌───────┼────────┐
       ▼       ▼        ▼
    Employee  Balance  History
```

In a real backend, these responsibilities would eventually become:

```text
Frontend
   ↓
API
   ↓
Views / Controllers
   ↓
Business Logic
   ↓
Database
```

This project gives students the foundation for understanding that architecture.

# 20. Design Philosophy

The project was designed using one important rule:

> **Every function should have one clear responsibility.**

For example, don't create one huge function:

```python
employee_management_system()
```

containing 300 lines.

Instead:

```text
display_employees()
apply_leave()
check_leave_balance()
employee_details()
display_leave_history()
```

Each function handles one responsibility.

This makes the application:

- Easier to understand
- Easier to test
- Easier to debug
- Easier to modify
- Easier to extend

# 24. Suggested Teaching Order

Don't teach the complete project in one shot.

Build it progressively.

### Stage 1 — Data Structures

Teach:

```text
Dictionary
List
Tuple
Set
```

Build the basic data.

---

### Stage 2 — Menu

Teach:

```text
while True
match-case
enumerate()
```

Build the menu.

---

### Stage 3 — Functions

Convert menu operations into functions:

```text
display_employees()
apply_leave()
check_leave_balance()
employee_details()
```

---

### Stage 4 — Function Arguments

Introduce:

```text
Positional arguments
Default arguments
*args
**kwargs
```

---

### Stage 5 — Return Values

Introduce:

```python
get_employee()
employee_exists()
validate_leave()
```

Students learn that functions don't always have to print something; they can **return data**.

---

### Stage 6 — Generator

Introduce:

```python
yield
```

Create:

```python
leave_history_generator()
menu_generator()
```

---

### Stage 7 — Decorator

Finally introduce:

```python
@log_activity
```

Students can now understand why decorators are useful.
